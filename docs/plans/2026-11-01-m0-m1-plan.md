# arioso M0 and M1 Implementation Plan

**Goal:** a working local speech stack, built in the order the PRD sets out: model
management first, then Piper text to speech behind an HTTP and WebSocket API.

**Architecture:** a Cargo workspace of small crates. Engines sit behind traits in
`arioso-core`; `arioso-models` owns the catalog, cache, and downloads; `arioso-cli`
is the binary; `arioso-server` (M1) exposes the HTTP surface. No crate reaches into
another's internals.

**Stack:** Rust 2024 edition, tokio, reqwest with rustls, ed25519-dalek for manifest
signatures, ort for ONNX inference, axum for HTTP, utoipa for OpenAPI.

**Status:** M0 is done except the signing tool and the server-side progress feed.
Mistakes that cost time are recorded in `docs/lessons.md`; read it before repeating
a build or test setup from scratch.
M1 tasks 1.1 to 1.6 and 1.8 are done: phoneme table, CMUdict, ARPAbet mapping,
sentence chunker, Piper inference, the HTTP surface, and `arioso say`.
`arioso serve` answers on 127.0.0.1:10101, returns WAV from `POST /v1/tts`, and
streams PCM from `/v1/tts/ws`. Task 1.7 is done, so the M1 definition of done
is met except the golden-audio test and two `say` flags (`--voice`, `--play`)
that the config already covers.

Still missing: letter-to-sound for words outside CMUdict. Every proper noun
currently drops out of the sentence.

Next is M1.5, specified in PRD F14: text normalization and the user dictionary,
tasks 1.9 to 1.14 below. Letter-to-sound stays after it, because normalization
removes the digit case and the user dictionary gives an escape hatch for the rest.

Two deviations from the tasks below, both deliberate:

- There is no `TtsEngine` trait yet. One implementation does not need a trait;
  it arrives with the second engine, Kokoro.
- Task 1.5 has no golden-audio test. It needs a reference render and an ear, so
  the check for now is that the output is not silence and sounds right.

### Task 1.3: ARPAbet to the model's IPA inventory

**Objective:** map CMUdict output onto the characters the Piper voice expects.

**Files:**
- Create: `crates/arioso-g2p/src/arpabet.rs`

**Constraint found while checking the real voice:** `en_US-lessac-medium` maps 154
single symbols. There is no entry for `aɪ`, `oʊ`, `tʃ`, `dʒ`, `eɪ`, `ɔɪ`, `aʊ`, or
`iː`, because those are sequences of single symbols with `ː` appended for length.
The mapping must therefore emit one symbol at a time: `EY` becomes `e` then `ɪ`,
`CH` becomes `t` then `ʃ`, and stress is a separate `ˈ` or `ˌ` symbol placed before
the syllable.

**Steps:**
1. Failing test: `HH AH0 L OW1` becomes `h ə l ˈ o ʊ`, with the stress mark its own
   symbol and the diphthong split.
2. Failing test: every symbol the mapping can emit is present in the voice
   inventory. Embed the 154-symbol list as a constant in the test; it is derived
   data, not a model weight.
3. Implement the table, then drop phonemes the model does not know.
4. Run `cargo test -p arioso-g2p`.
5. Commit: `feat(g2p): map ARPAbet to the voice inventory`.

Rhoticity and vowel length are judgement calls until the golden-audio test in task
1.5 can judge them: `ER` is written `ɚ` when unstressed and `ɜ` plus `ɹ` when
stressed, and that choice needs an ear, not a table.

## M3. Config, engines, and the API document

Milestone M3 in the PRD: "`/v1/config` PATCH with persist, `/v1/engines`, engine
selection, `arioso doctor`, OpenAPI complete with Swagger UI". Exit criterion: "Config
change switches engine without restart and survives restart".

The exit criterion names an engine switch, and only one engine is built. Kokoro is M4.
This milestone therefore builds the switch mechanism and the surfaces around it, and
reports honestly what can be switched to: `tts.engine` accepts the engines the binary
holds, which is `piper`, and any other value is refused with the reason. M4 adds Kokoro
and the switch becomes real without changing the API.

### 3.1 The API document and Swagger UI (done)

`utoipa` derives a schema from the handler signatures and the request and response types,
`utoipa-swagger-ui` serves it. The document is the contract the PRD's endpoint table
promises, so it has to cover every route that exists, including the two WebSockets
described by hand because they have no request body to derive from.

- [x] `GET /openapi.json` serves OpenAPI 3.1.
- [x] `GET /docs` serves Swagger UI against it.
- [x] Every route that exists is in the document, with its errors as the RFC 9457 shape.
- [x] The document is generated from the code, not written beside it, so a new route
      cannot be missing from it.
- [x] A test asserts the document parses and names every registered path.

### 3.2 `GET /v1/info` and `GET /v1/engines` (done)

Two read-only surfaces that describe the build and what it can do.

- [x] `/v1/info`: version, build target, and the engines compiled in.
- [x] `/v1/engines`: per engine, whether it streams, its languages, its voice count, and
      whether a model is loaded right now.
- [x] The engine list is built from the code that can serve requests, not from the
      catalog, so a model file on disk does not invent an engine.

### 3.3 `GET /v1/voices` (done)

- [x] Voices for the active engine, from the manifest, with id, tier, rate, and licence.
- [x] `?language=en_US` filters, matching the manifest's language list.
- [x] The active voice is marked, so a client can render a picker without a second call.

### 3.4 `PATCH /v1/config` (done)

The config is immutable in `AppState` today, which is why a change needs a restart. This
slice makes it mutable and applies what can be applied without one.

- [x] Partial update: only the fields present in the body change.
- [x] Unknown fields are refused rather than ignored, so a typo in a key does not look
      like a successful change.
- [x] Validation runs before anything is applied, and a rejected patch changes nothing.
- [x] `persist: true` writes the config file atomically, so a crash cannot leave a
      half-written file.
- [x] A voice change drops the loaded voice, so the next request loads the new one.
- [x] `tts.engine` accepts only what the binary can serve, and names the alternative.
- [x] `GET /v1/config` returns the effective config with secrets redacted.

### 3.5 Review, documentation, and the retrospective (done)

- [x] Read the whole surface for defects, fix them in separate commits.
- [x] `README.md` and `examples.md` with captured output for every new route.
- [x] The lesson file for whatever cost time.

## M5. Hardening: fuzzing, and a log that says something

The server parses four kinds of untrusted input and, until now, has been tested only with
inputs a person thought of. This milestone assumes a hostile one.

### 5.1 Fuzz the API (not started)

- [x] 5.1.1a Hostile-input tests on stable for the three JSON parsers: every prefix of a
  valid document, one byte replaced at a time, and nesting deep enough to blow a recursive
  parser. Runs in CI in under a second, and a panic fails it.
- [x] 5.1.1b `cargo-fuzz` targets with coverage guidance: `config_json`, `dictionary`,
  `manifest`, `wav_header`, seeded from a real document each. 17.7 million executions in
  four 71-second runs, zero crashes, empty artifact directories.
- [x] 5.1.7 The findings from the security pass: engine error detail, config paths in
  responses, security headers, the manifest name join, and a switch for the API document.
  The connection cap stays open; it needs the accept loop.
- [ ] 5.1.2 A target over the router itself: random bytes into `/v1/tts`, `/v1/stt` and
  `PATCH /v1/config` must always produce a problem-details response, never a panic and
  never a hang. Run in process, so it needs no socket and no model.
- [ ] 5.1.3 A target over the WebSocket frame protocol, including the `cancel` frame and
  a client that sends binary frames where JSON is expected.
- [ ] 5.1.4 Seed corpora committed under `fuzz/corpus/`, so a run starts from real
  documents rather than random bytes.
- [ ] 5.1.5 Nightly CI job with a fixed time budget (5 minutes per target), reporting to
  the job summary. A crash artifact is a failing job, not an email nobody reads.
- [ ] 5.1.6 Every crash becomes a regression test in the crate it belongs to, named for
